# 项目 B｜AI 外呼与企微线索承接产品

性质：真实工作经历复盘 + 个人机制原型。工作职责按最新简历：全流程参与，重点主导 A-D 分层分流与整通最终意向评测；参与对话、摘要、企微与转人工方案。

## 1. 业务问题

外呼判断出意向后，还需要让销售知道“用户想要什么、凭什么这样判断、下一步谁来做”。标签正确但任务无人接手，或者摘要遗漏关键条件，都可能导致业务价值未实现。

已记录的典型问题为“观望误判拒绝”。用户进一步确认的改动是：客户未明确拒绝，仍在询问价格等信息时，不能直接判无意向。需要保留咨询信号，结合整通语境判断。价格咨询不自动等于高意向，未拒绝也不等于后续联系许可。

## 2. 输入输出与分流方案

输入：线索来源与标识、已有客户资料、整通对话、触达资格、可用承接渠道、人工容量。输出：有证据的意向状态、需求字段、缺失项、下一步任务、负责人/截止时间和回写事件。

下面是作品集的建议分流表，展示决策方法，不替代原工作系统 A-D 的精确定义：

| 情形 | 需要保留的证据 | 下一步 |
| --- | --- | --- |
| 明确需求且同意后续联系 | 需求、时间窗口、同意表达 | 校验承接条件后进入销售/企微流程 |
| 有兴趣但时间未定 | 兴趣与顾虑、允许的联系方式 | 澄清或进入有条件的后续培育 |
| 当下不方便 | 可联系时间与是否同意回拨 | 征得确认后创建回拨任务 |
| 要求人工 | 当前诉求和已确认事实 | 检查容量；坐席接受后才算转接成功 |
| 明确拒绝后续联系 | 原话、时间和范围 | 停止后续触达并取消相关待执行任务 |

## 3. 编排与状态设计

主链路：资格校验 → 发起外呼 → 提取事实/意向 → 决定承接方式 → 执行动作 → 接收渠道结果 → 销售领取/首次联系 → 回写。

状态示例（补充设计）：待触达、通话中、待澄清、待承接、企微邀请待结果、已添加、待销售领取、已领取、已联系、暂停/拒联、执行失败。

“已生成邀请”不能写成“已添加”；“已派发”不能写成“已领取”；“已安排回拨”不能写成“已联系”。每次写入需要任务标识、防重复键、来源事件和可恢复的失败状态。

## 4. 模型、规则和人工分别做什么

模型适合理解自然表达、抽取字段、整理摘要与澄清建议；确定性逻辑负责触达资格、状态变化、渠道回执、任务防重及容量；人工负责模糊高价值诉求、争议标注和业务确认。当前原型主要由规则运行，不能描述为已验证真实模型编排。

## 5. 评测层次

| 层次 | 评什么 | 验证方法 |
| --- | --- | --- |
| 信息与意向 | 字段证据一致性、最终意向、高意向漏判 | 独立标注整通对话；报告样本量、类别分布和混淆矩阵 |
| 动作与状态 | 路由正确、拒联阻断、回拨同意、写入防重 | 正常与异常流程回归，不只看回复文本 |
| 人工承接 | 坐席接受、首次联系时效、销售退回原因 | 任务事件与业务反馈关联，区分派发与接手 |
| 业务价值 | 单位有效线索总成本、净人工分钟数 | 可比试点与观察窗口；扣除复核及返工时间 |

历史工作记录：整通最终意向约 75% → 约 90%，为同一批人工抽检样本复测；人工介入率 35% → 15%，为项目整体。原始样本量、观察窗口和指标 SQL 尚待归档；不将数字归为懂车帝专属或独立因果效果。

## 6. 当前 Demo 能证明什么

DriveReach：二手车卖车文本对话、字段证据、改口、转接/回拨、拒联、任务持久化与容量模拟。历史工程测试 32 项；40 条合成规则案例中，开发 24/24、首次留出 14/16。两个失败为词表外车型和里程缩写，原型会保留缺失。

DriveFollow：购车顾问准备建议、核对来源、创建跟进与模拟试驾。用于补充销售侧机制。

当前未形成一个接入真实企微的连续外呼演示；作品集用流程图和状态说明呈现企微编排，用现有 Demo 验证相邻机制。购车主线与卖车原型不合并统计。

## 7. 下一步优先补强

优先补一份脱敏主案例：原始用户表达 → 原标签和分流 → 实际问题 → 个人作出的规则修改 → 复测结果。其次补充真实企微回执和销售任务字段。最后再接入沙箱接口，验证邀请、添加、领取和联系各状态。

## 8. V2.1 主案例：价格咨询中的模糊意向

本人已口述确认：未明确拒绝且涉及价格等咨询时，不直接判无意向。既有简历支持本人主导标签、分流和最终意向评测。以下把规则原则细化为可解释的产品案例。

模拟 Query：“有点贵啊，最近也不急着买。现在有优惠吗，算下来落地大概多少？”

可确认的是价格顾虑、优惠与落地价咨询，以及近期不急。购买强度、具体时间和渠道许可仍需澄清。假设知识库只有指导价和过期活动，系统应说明缺少有效报价，补城市/配置等必要条件，再询问是否接受人工核实。不能把回答不了直接记为客户无意向，也不能凭问价自动发企微邀请。

| 证据项 | 当前内容 | 状态 |
| --- | --- | --- |
| 真实问题与职责 | 观望误判拒绝；主导分层分流与整通意向评测 | 用户确认与简历记录 |
| 具体修改原则 | 未明确拒绝且仍问价格等信息，不直接判无意向 | 本次口述确认 |
| 场景和 Query | 价格顾虑、优惠、竞品、月供、置换、代问、拒联等12类 | 人工模拟，非原始日志 |
| RAG 与意向字段 | 意向、咨询主题、答案有效性、许可及动作分别输出 | 本轮补充设计，非原系统字段证明 |
| 完整承接流程 | 澄清报价条件，询问许可，核实并发送，跟踪回执 | 模拟复原，企微接口尚未验证 |
| 分类结果 | 咨询漏判、弱咨询误升高优、知识故障误降意向 | 验证方案；没有新增实测结果 |
| 历史整体复测 | 约75%→约90%，同批人工样本 | 工作记录，不归因于单处修改 |

关键取舍：保留未被明确拒绝的咨询机会，同时避免把弱咨询、代问和不愿继续的客户推入高优销售队列。明确拒联应覆盖先前兴趣；同意已有企微发一次报价不代表同意继续电话营销。

完整模拟对话、12条Query、正反例、标注建议与面试讲述见 [模糊意向与RAG分流案例](10_模糊意向与RAG分流案例.md)。模型契约及评测计划见 [AI方案与上线验收](09_AI方案与上线验收.md)。
