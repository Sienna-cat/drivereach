# 主案例深化｜模糊意向、价格咨询与 RAG 分流

版本：V2.1，2026-11-23。以下 Query、对话、字段和处理路径为按用户确认规则编写的模拟案例，用于作品集讲述、方案讨论和评测种子。没有执行模型测试，不含新增线上效果。

## 1. 已确认的个人改动

用户补充的规则要点：客户没有明确拒绝，且涉及价格等咨询时，不能直接判为无意向。

作品集可采用的表达：**我调整了模糊意向的判定与分流口径：客户未明确拒绝、仍在询问价格等信息时，不直接判定为无意向，保留咨询信号，再结合上下文决定是否澄清和如何承接。**

进一步的产品设计是将“客户意向”与“知识库是否能回答”分别记录。RAG 未命中、过期、冲突或工具超时反映的是系统回答能力，不能直接作为客户无意向的证据。该字段拆分与下文交互是本轮补充方案，原系统的字段名、Prompt 和实现方式没有新增证据。

需要守住两个判断：没有明确拒绝仍可能是未知；询问价格说明有咨询行为，单独不能证明高购买意向。

## 2. 主案例：价格顾虑被过早归为无意向

背景设定：购车线索外呼，客户尚未说明预算、购车时间及后续联系方式。知识库仅有指导价和已过期的地区活动，不能确认当前门店实际落地价。以下均为模拟复原。

| 轮次 | 对话 / 系统处理 | 可支持的判断 |
| --- | --- | --- |
| T1 助手 | 您之前关注过这款车，现在主要想了解哪方面？ | 开放式了解需求；不预设高意向 |
| T2 客户 | 有点贵啊，最近也不急着买。现在有优惠吗，算下来落地大概多少？ | 价格顾虑 + 优惠/落地价咨询；近期不急，具体时间未知；没有明确拒联 |
| 检索结果 | 只有指导价，活动已过期，缺少当前地区与配置的有效报价 | answer_status=needs_verification；不据此改变客户意向 |
| T3 助手 | 您关心的是优惠后的总价。我这里没有这款配置当前有效的落地报价，不能直接给您报准确数字。您主要看哪款配置、在哪个城市？ | 说明回答范围，只补会影响报价的必要条件；不编造优惠 |
| T4 客户 | 杭州，入门版，先了解下，合适再考虑。你们企微我之前加过。 | 地区/配置明确；价格条件成立才考虑；已添加企微为客户自述，系统仍需核实 |
| T5 助手 | 明白，您主要在比较总价。如果您愿意，我可以请顾问核实杭州这款配置的报价；您希望现在转接，还是通过已经添加的企微接收？ | 提供承接选择；只有系统确认已添加企微时才提供该选项，否则改为询问是否愿意添加 |
| T6 客户 | 先不用转，发到已经加的企微上吧。 | 仅许可本次通过已有企微发报价资料；不授权电话回拨或无限营销 |

最终交接包：杭州/入门版、价格顾虑、先了解合适再考虑、报价尚待核实、当前未确认购车时间、客户同意本次已有企微报价、原话与轮次。资格和实际好友关系检查通过后，生成“核实并发送报价”任务；渠道回执与销售领取单独记录。

模拟失败路径：把“贵”“不急”当成终止条件，或把价格问题回答不了作为无意向依据 → 关闭线索。这里用于解释待修复的逻辑，不声称原系统存在这条精确代码或一定因 RAG 未命中误判。

修正路径：完整保留“顾虑 + 继续咨询” → 分别评估意向和可回答性 → 核对报价条件 → 按客户许可承接。到 T2 只能确认存在咨询信号；到 T6 才取得本次企微发送许可。

## 3. 修改前后的决策口径

“修改前”列是用来说明问题的简化反例，不是原系统配置截图；“修改后”中的原则来自用户确认，具体字段和流程为补充设计。

| 判断点 | 应避免的失败口径 | 完善后的口径 |
| --- | --- | --- |
| 负向词 | 看到“贵、再看看、不着急”直接判无意向 | 结合后续问题，区分顾虑、时间未定与明确拒绝 |
| 知识型咨询 | 没有明确购买承诺，忽略价格/优惠问题 | 记录咨询信号与待解决问题；购买强度仍独立判断 |
| RAG 结果 | 无答案、低检索分或超时 → 无意向 | 只影响回答方式与核实任务，不直接影响意向标签 |
| 高意向判定 | 问价格 → 高意向 → 立即加微/转人工 | 结合明确需求、行动意愿、时机及业务字典；问价本身不够 |
| 触达许可 | 未拒绝 → 默认同意后续联系 | unknown / allowed / denied，按渠道和本次用途记录 |
| 最终输出 | 只有有意向/无意向 | 意向状态、咨询主题、顾虑、答案状态、许可和动作建议分别输出 |

## 4. 12 条模拟 Query 与标注建议

下表是人工编写的预期草案，不是评测结果。每条的背景也是模拟设定；真实标注时必须看完整会话。

| ID | 模拟 Query | 意向与知识判断 | 下一步 / 必须避免 |
| --- | --- | --- | --- |
| Q01 | 有点贵，最近也不急。现在优惠后落地多少？ | 价格咨询 + 顾虑，购买时机未定；缺实时门店报价 | 澄清城市/配置，提供核实路径；不判无意向、不编报价 |
| Q02 | 现在肯定不买，年底有活动的话再看看。去年那种优惠还会有吗？ | 条件性观望；未来活动无法由去年资料保证 | 回答已知范围，后续提醒另征许可；不承诺未来优惠 |
| Q03 | 隔壁品牌便宜两万，你们到底贵在哪，能不能再便宜？ | 竞品比较 + 价格异议；价差未经同配置核实 | 询问对比车型/版本，引用有效差异；不以“嫌贵”结束 |
| Q04 | 月供两千以内我才考虑，要多少首付？有没有别的手续费？ | 条件性需求；贷款期限、额度和费用未明 | 记录月供约束，核实完整方案；不靠单项月供承诺成交 |
| Q05 | 我旧车还能抵多少？算上补贴合适才换。 | 条件性置换需求；旧车估值与补贴资格未知 | 核实评估/政策条件，征得同意后给人工报价；不把政策上限当实际权益 |
| Q06 | 先不买，我就是问问这车多少钱。 | 弱咨询，购买意向未知；有有效指导价也不等于落地价 | 回答范围内信息，可轻量澄清；不自动高优或派销售 |
| Q07 | 不是我要买，是帮同事问价，你别给我安排销售。 | 本人非购买者，代咨询；明确拒绝销售安排 | 提供可答信息，停止销售派发；不把问价认成本人需求 |
| Q08 | 嗯，再说吧。 | 信息不足，可能是礼貌结束；无确定兴趣证据 | 尊重结束信号；必要时一次简短确认，不反复追问、不虚构拒联范围 |
| Q09 | 暂时不需要，也不想了解了。 | 明确当前无需求、拒绝继续介绍；永久全渠道拒联范围未明 | 结束本次营销，不自动建回访；不因未说“永远”而继续劝说 |
| Q10 | 再便宜也不买，以后不要再打电话了。 | 当前明确拒绝 + 电话拒联；知识状态不改变该判断 | 停止电话并取消相关排期；其他渠道无许可也不得绕过联系 |
| Q11 | 不要再打电话，报价发我已经加的企微就行。 | 报价咨询继续；电话 denied，已有企微本次报价 allowed | 核实好友关系后按限定用途发送；不全渠道关闭，也不继续电话 |
| Q12 | 你刚才说优惠一万，页面写的是两万，杭州今天到底按哪个？ | 持续咨询 + 资料冲突；不能选择更有利数字作答 | 对照地区/版本/有效期与适用条件；未解决转人工核实，保留冲突 |

建议追加的噪声变体：口头停顿、ASR 将“能不能”识别为“不能”、多轮改口、长对话摘要漏掉后半句。它们属于后续扩充方向，本版不声称已覆盖真实语音质量。

## 5. 关键反例：兴趣不能覆盖后续拒绝

模拟 T2 客户：“现在优惠多少？”——此时是价格咨询，意向待澄清。

模拟 T4 客户：“不用了，我已经买别家的了，以后不要再联系。”——更新为当前无购买需求、明确停止后续联系，取消相关待执行营销任务。T2 只作为历史证据保存，不能继续用于证明当前仍愿意接收报价。

另一条边界：客户说“别打电话，发已有企微”是渠道与用途选择；客户说“什么都别发”才是更广的拒联范围。具体范围必须引用原话，不能凭方便执行而扩张或缩小。

## 6. RAG、意向与分流怎样协作

整通对话进入两个独立判断维度：语义侧抽取需求、顾虑、时机与许可；知识侧提取问题、检索资料并检查适用性。二者由分流规则组合，不必实现为多个独立 Agent。

| 知识状态 | 可做的回答/动作 | 对意向的影响 |
| --- | --- | --- |
| 有适用且有效的证据 | 引用来源回答，区分指导价/补贴上限/实际报价 | 仍按客户表达判断，不因答出而升高 |
| 查询条件缺失 | 补城市、配置、支付方式等必要字段 | 保留当前意向或未知，不降为无意向 |
| 未命中或未覆盖实时信息 | 明确缺口，询问是否接受人工核实 | 不是拒绝证据；也不默认创建人工任务 |
| 来源过期或冲突 | 暂缓承诺具体数值，核对版本、地区、有效期、资格 | 不把系统问题归到客户意向 |
| 检索工具失败 | 标记错误；有限重试或提供人工选项 | 不输出“客户无意向”掩盖故障 |

“不由 RAG 结果直接判无意向”不表示回答内容完全不影响后续判断。客户在获得真实信息后明确表达拒绝，应根据新的客户表达更新；需要区分系统状态与客户态度变化。

## 7. 评测如何对齐这次修改

将以上案例标为 development_seed / synthetic / not_run。它们参与了方案设计，不能再充当独立未见验收集。开发时可验证边界；正式效果需要真实整通、独立标注与冻结新样本。

- 重点问题：人工标为存在咨询/观望信号，却被系统终止为无意向的比例；同时分开报告“未知”与“明确当前无需求”。
- 反向错误：弱咨询、代问被升为高优的比例；明确拒联后仍派任务；不该转人工而转人工的负载。
- 知识回答：无有效来源却给出价格、过期活动承诺、检索状态误报、引用内容与报价条件不一致。
- 承接质量：未获许可就邀请/回拨、渠道选择错误、销售退回原因、核实与接手耗时。
- 同一客户语义不变的成对检查：分别给“有效知识”“未命中”“工具错误”。预期意向不因知识状态直接改变，回答和核实动作应按状态变化。
- 相同问价句不同上下文的对照：本人考虑买、代朋友问、明确不买、先咨询后拒联，不能由关键词得到相同标签。

历史整体约75%→约90%仍按原同批复测口径讲述；本轮没有新增该错误类别的改善比例，也不将模拟案例数量当成样本通过数。

## 8. 面试讲述稿

我主导线索分层分流和整通最终意向评测时，关注过观望用户被判成拒绝的问题。我调整的一条判断口径是：用户没有明确拒绝，又在问价格、优惠等信息时，不能直接判成无意向，要保留这类咨询信号。

为了说明这个判断，我用一个模拟场景：客户说“有点贵，最近也不急，优惠后落地多少”。前半句是顾虑和时间态度，后半句仍在咨询。系统需要分别判断客户意向与知识库能否回答；如果没有当前门店报价，应说明限制、补必要条件、询问是否接受核实，而不是把回答不了写成客户没兴趣。

我也会控制另一侧错误：问价不自动等于高意向，未拒绝不自动等于同意加微。实际分流还要看明确需求、渠道许可和承接条件。作品集把这一原则细化成字段和评测案例，具体示例是场景复原。工作记录中的整体准确率约75%到约90%为同批复测，我不会把全部变化归因于这一个改动。
