# 从意向判断到销售任务｜V3 补充方案

性质：个人产品设计与静态界面示意。依据已确认的模糊意向规则和模拟对话展开，没有新增生产接口或真实任务结果。

## 1. 为什么补这一页

模糊意向判断正确后，销售仍需要知道要处理什么、依据是什么、哪些内容尚未核实，以及客户允许哪种联系方式。任务设计把识别结果与下一岗位连接起来。

主册第5页呈现客户证据如何逐步增加；第6页说明语言理解、知识检索和路由的分工；第8页展示销售实际接手的任务结构。三页共用同一模拟案例。

## 2. 同一条线索的推进记录

| 时点 | 新增证据 | 当前判断 | 可以执行的动作 |
| --- | --- | --- | --- |
| 客户问优惠后落地价 | 有价格顾虑，近期不急，继续咨询 | 购买意向待澄清，存在咨询信号；渠道许可未知 | 说明可回答范围，澄清城市与配置 |
| 客户补充杭州、入门版、合适再考虑 | 报价条件更明确，存在条件性考虑 | 购车时机仍未确定；实际报价待核实 | 询问是否愿意接受顾问核实，提供渠道选择 |
| 客户说发到已加企微 | 本次报价发送许可；已加关系为客户自述 | 限定渠道与用途的许可 | 系统核实好友关系、资格和队列条件 |
| 检查通过并建立任务 | 关联线索、证据、队列与任务ID | 待领取；报价尚未确认 | 分派到对应队列，追踪领取和时限 |
| 销售领取并核实报价 | 责任人、有效来源、地区配置与适用条件 | 资料可发；仍不证明近期购买 | 按已获许可的渠道发送；等待实际回执 |
| 渠道回执和销售反馈 | 送达、失败、客户回应或后续结果 | 分别记录发送结果和业务进展 | 联系结果按业务定义回写，不自动从送达推导成交 |

主册的任务卡停在“待领取”，因此不会预填已核实报价、已发送或客户已回应。真实接入时，负责人和截止时间由队列规则生成；本版没有编造门店 SLA 数值。

## 3. 销售承接卡的字段

| 字段 | 在本例中的内容 | 设计目的 |
| --- | --- | --- |
| 任务目标 | 核实杭州入门版有效落地报价，并按本次许可发送 | 让销售知道交付物 |
| 客户事实 | 先了解，价格合适再考虑；具体购买时间未定 | 减少重复询问与意向夸大 |
| 原话与轮次 | 客户咨询、条件、许可原话分别关联 | 支持核对判断和处理争议 |
| 未解决事项 | 当前有效报价，金融/补贴资格等适用条件 | 不把待核实信息包装成事实 |
| 渠道与用途 | 已有企微、本次报价；后续电话许可未知 | 约束允许的动作范围 |
| 状态与责任 | 待领取，门店报价队列；领取后负责人和时限 | 支撑派发、超时与接续 |
| 知识依据 | 取得有效来源后记录版本、地区、配置和时间 | 防止过期价格与错误承诺 |
| 结果回写 | 已领取、已核实、发送结果、客户回应、退回原因 | 连通业务反馈和后续评测 |

## 4. 已加和未加企微的两条路径

已有好友：在系统核实关系和资格后，按客户本次明确许可进入任务；发送后等待真实回执。客户说“我加过”是线索，不能直接当成系统核验通过。

尚未添加：先询问是否愿意添加，再创建邀请并记录结果。邀请生成、添加成功、销售领取、完成联系是不同事件。客户没有答复时不把许可写成同意。

不同任务的准备可以并行，但所有外部发送动作都必须等待前置条件满足。报价核实完成不代表可以绕过渠道许可。

## 5. 必须设计的异常

| 异常 | 恢复路径 | 检查重点 |
| --- | --- | --- |
| 队列无人领取 | 保留未领取状态，按队列策略提醒或重新分配 | 防止派发即算成功 |
| 领取后长期无结果 | 暴露超时与负责人，进入人工跟进 | 不能从发送次数推算有效承接 |
| 报价来源冲突或过期 | 暂停具体价格承诺，继续核实 | 错误报价不能被当作自动化成果 |
| 客户自述已加但关系未查到 | 确认账号/归属；需要新添加时另征许可 | 不创建“已添加”假状态 |
| 发送超时，结果未知 | 查询 request_id 与渠道结果，再决定是否重试 | 防止重复发送 |
| 客户新增拒联 | 更新资格并取消相关未执行动作；执行前再次校验 | 旧许可不能覆盖新的明确拒绝 |
| 销售退回为非本人需求 | 保留代问证据，修正标签与队列策略 | 防止只优化咨询召回而增加无效任务 |

## 6. 产品取舍及验收

保留咨询信号可以降低过早关闭的风险，但如果所有问价都进入高优人工池，会提高销售负载。因此需要联合看咨询漏判、错误高优承接、退回原因和净人工耗时。

首期优先把一条任务从理解到回写走通，再扩量。建议先做影子回放与人审试点：比较销售是否能直接理解并处理任务，记录补问、修改、退回、耗时和失败恢复。不以“卡片已生成”代替任务完成。

这份设计本轮没有执行真实顾问研究，也没有把可读性判断当成用户体验数据。后续回放可用同一任务结构采集证据。
